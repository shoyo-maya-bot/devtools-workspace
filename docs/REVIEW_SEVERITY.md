# レビューの重要度（MUST / WANT / NITS / Q）

レビューの指摘には、次の 4 つのどれかを付けます。ツール・プロンプト・人のレビューで同じ意味に使います。

| 重要度 | 意味 | 例 |
|---|---|---|
| MUST | 直さないと実装・試験・運用で問題（不具合・事故）が起きる。直すまで先に進めない | 必須項目の抜け、認可の漏れ、設計書とコードの食い違い |
| WANT | 直すと良くなる。直さなくても動くが、直すことを勧める | 読みにくい構成、足りない説明、性能の余裕 |
| NITS | 表記・体裁などの軽微なもの | 誤字、用語の揺れ、表の書式 |
| Q | 指摘ではなく質問。情報が足りず判断できないもの | 「この上限は業務で決まっていますか？」 |

- 迷ったら軽い方にする。推測だけで MUST にしない（書いていないことは「記載が無い」、判断できなければ Q）
- 最終的な判断（採択・不採択）は人が行う
- 各リポジトリのプロンプトに書いた短い説明は、この表の言い換えです。意味を変えるときはこのファイルを先に直します
