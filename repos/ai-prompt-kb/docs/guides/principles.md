# 原則（重要）

## 4 つの原則

1. **固有名を入れない**: 社名・内部パッケージ名・ジョブ ID・内部ライブラリ名・リポ URL 等は
   収録しません。埋めるのは自社の値だけにしてください。
2. **「差異なき複製」を目的にしない**: ここにあるのは一般設計のたたき台です。実在資産の逐語コピーではありません。
3. **権利・許可の書面は保管**: 持ち出し・再利用の可否は所属先の規程と契約に従ってください。
4. **機密を書かない**: `.env` はコミットしない。秘密情報はコード・ドキュメントに直書きしない
   （テンプレートは `<your-value>` のようにする）。

## 機械チェック（CI で必須）

原則は人のレビューだけに頼らず、`python scripts/kb.py validate` で自動検査します。
ルールの正は `kb.config.yaml` です。

| チェック | 内容 |
|---|---|
| クリーンルーム文言 | 全プロンプト本文に「特定企業の写しにはしないこと」を含む |
| 禁止パターン | 秘密鍵・各種トークン・認証情報の直書き・社内ドメイン URL を検出 |
| `.env` 混入 | `.env` / `.env.*`（`.env.example` 以外）が存在したらエラー |
| 前提の明示 | 本文に `{{ }}` プレースホルダと「# 私が埋める前提」見出しがある |

!!! tip "自組織の固有名を禁止リストに追加する"
    `kb.config.yaml` の `forbidden_patterns` に自社名・内部パッケージ接頭辞・ジョブ ID の書式などを
    正規表現で追加すると、混入を CI で止められます。
