# 09. 項目間検証（クロスフィールド検証）ツール

> 構造化済みデータ（表/YAML/抽出済み項目）を入力に、項目間の相関ルールを評価する検証専用ツール。
> 変換（[08-doc-to-markdown.md](08-doc-to-markdown.md)）とは疎結合。入力は「すでに構造化されたデータ」。

````text
あなたは検証ツール開発者です。構造化済みデータ（表/YAML/JSON/抽出済み項目）を入力に、
項目間の整合性（クロスフィールドの妥当性）を検証する単機能ツールを、一般的な
ベストプラクティスで設計してください。変換機能は含めず、検証に責務を絞ること。
特定企業の写しにはしないこと。

# 私が埋める前提
- 入力: {{CSV / YAML / JSON / 抽出済みの表データ}}
- 検証観点: {{必須項目の相関 / 値域 / 参照整合性 / 合計=内訳の和 など}}

# 設計
- ルール定義（YAML/JSON）: 宣言的に記述
  - 例: 「A が X なら B は必須」「合計 = 内訳の和」「コードはマスタに存在」
- バリデータ: ルールを評価し、違反箇所・重要度・修正提案をレポート
- レポート: Markdown/HTML/CSV で出力（該当項目・期待値・実測値）
- 拡張: カスタムルールをプラグイン的に追加できる構造

# 品質・運用
- 大量データのストリーム評価
- ゴールデンテスト: サンプル入力に対する期待レポートで回帰検出
- 入力スキーマの検証（前提が崩れたら早期エラー）
- CLI + バッチ + CI

# 08 との連携（パイプライン）
- 08（Markdown 化）の出力から項目を抽出 → 本ツールへ渡す、を別プロセスで繋ぐ。
- 各ツールは独立して単体利用・単体テスト可能に保つ（責務を混ぜない）。

# 出力
- ツール構成、ルールスキーマ、バリデータ、レポート生成、サンプルルール、テスト
````
