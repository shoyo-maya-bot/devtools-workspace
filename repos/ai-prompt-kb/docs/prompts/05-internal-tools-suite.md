# 05. 開発支援ツール集（マルチレポ）

> 複数の独立した開発支援ツールを、それぞれ別リポジトリ（マルチレポ）で管理する構成を、
> 一般ベストプラクティスで設計するプロンプト。ローカルが「1ツール=1リポ」の前提に合わせる。

````text
あなたはツール基盤のアーキテクトです。複数の独立した開発支援ツールを、それぞれ別
リポジトリ（マルチレポ）で管理する運用を、一般的なベストプラクティスで設計してください。
特定企業の写しにはしないこと。

# 私が埋める前提
- 主要言語: {{例: Python / TypeScript}}
- ツールの例（一般カテゴリ、1ツール=1リポ）:
  - API 仕様の差分抽出ツール
  - 課題管理チケットの要約ツール
  - 表計算(Excel)の差分抽出ツール
  - 表計算(Excel)の一括置換ツール
  - レビュー結果の集約ツール
  - チャット向けアジェンダ生成ボット

# マルチレポ設計
- 1ツール=1リポジトリ（独立した README / CI / 依存 / リリース / 権限）
- テンプレートリポ（scaffold）を1つ用意し、新規ツールは複製して統一感を保つ
- 共通処理は「共有ライブラリを別リポで公開し、各ツールが依存として取り込む」
  （社内パッケージレジストリ or Git 依存）。フォルダ共有はしない
- 組織標準の共通化: 再利用可能ワークフロー（org の .github）と共通 lint/format 設定を
  テンプレートから配布
- 秘密情報: .env はコミットせず .env.example を配置（<your-token> など）
- 外部 API 連携は共有ライブラリでレート制限・リトライ・エラーハンドリングを共通化

# 各リポの標準構成
- CLI エントリ / 設定ファイル / 入出力スキーマ / ユニットテスト / README（使用例）/ CI

# 選定メモ（判断基準）
- マルチレポが向く: 権限・公開範囲・リリースサイクル・所有チームがツールごとに異なる／
  言語がバラバラ／セキュリティ境界を分けたい（← 今回の前提）
- モノレポが向く: 少人数で横断変更が多い／共通コード比率が高い／まとめて管理したい
  （その場合は tools/<name>/ 構成 + パス変更検知でツール単位の独立 CI）

# 出力
- テンプレートリポ（scaffold）一式
- 共有ライブラリリポの雛形（公開・バージョニング方法込み）
- サンプルツール1つの完成実装・テスト・CI
- 新規ツール追加手順（テンプレ複製〜公開）
````
